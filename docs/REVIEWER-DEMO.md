# Restricted reviewer demo — current checkpoint 2026-11-21

The normal Home Studio **Try the demo** entry selects a fixed fictional Atlas example. **Simulation** remains the default, separate from **Live demo**. Mode changes discard pending proposals and revoke consent; returning to Simulation restores the visitor's brief/source in tab memory. No editor/imported content, visitor key or arbitrary peer is part of this restricted demo.

Production stays disabled twice: static `/reviewer/status.json` is exactly `{"enabled":false}`, and `api/reviewer.ts` unconditionally returns HTTP 503. The handler has no credential/provider imports, environment access or activation switch. A changed client status alone cannot activate public inference. No real model has been called.

The current offline enabled browser protocol is `{enabled:true,protocol:"tower-synthetic-v1"}`. After fresh explicit consent, start accepts only `{consent:true}`. Subsequent requests contain only an opaque expiring `{ticket,step}`, never client-selected models, routes, prompts, tools or keys. A best-effort bounded cancel request invalidates the run; timeout/disconnection does not prove remote rollback. Requests omit cookies/authorization, reject redirects and never silently switch to Simulation or retry.

The offline server reconstructs fixed requests for Reception → Home builder → Reception using Meta Model API's protocol and a trusted quota reservation port. This port has only scripted implementations in this repository. The owner selected Meta; OpenRouter documentation research was superseded before any implementation/use. No Muse endpoint, data, credential or quota is reused. See [Meta gateway and actual authorization gaps](META-REVIEWER-GATEWAY.md).

The existing Tower-patched nsdeploy Engine still orchestrates both agents in the browser. Its trusted host-only adapter injection requires caller, source, router and adapter origins to match; imported network metadata cannot authorize it. This is a Tower extension with recorded source provenance and preserved Apache attribution, not upstream compatibility certification. The portable manifest still describes the development mock router; a future live default must have accurate tested metadata.

A proposal requires matching HomeBundle text/action arguments, an actual successful registered validate_home_bundle dispatcher receipt and strict program validation. **Validation receipt** exposes the local action result. This receipt does not attest model execution or server persistence. Review, explicit Apply, revision conflict protection, safe text preview and JSON export remain separate. Drafts remain in tab memory.

The browser tests now use the actual offline gateway core and scripted Meta Responses port, not merely a canned successful HTTP answer. They verify the three-call sequence, ticket-only payloads, no private editor sentinel/key/cookie, disabled/denied behavior, 429/503/refusal/schema/network failure, cancellation, deadline and explicit restart. Unit tests cover stricter server origin/body/schema/quota/ticket/concurrency/expiry/response checks. Model IDs, adapter real-mode flags and fixture quota grants are not evidence that inference or free-credit accounting occurred.

Before any real single-run trial, an existing authorized Tower-specific server binding and actual free-credit amount/expiry/no-paid-overage enforcement must be confirmed. Then a bounded secret-free provider/atomic quota adapter must be reviewed and tested; the offline in-memory counters cannot guarantee public cross-instance budgets. Public inference remains a separate later acceptance/authorization step. Full canonical schema/streaming support, independent deployed HTTPS composition and judging-period capacity remain open. No private login/DB, public Home listing, license change or submission was added. P0 remains incomplete.
