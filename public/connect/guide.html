Build a home from another website.

This fixed-example browser mission runs a public Reception and Home builder network from a second origin. The caller owns inference; the peer supplies data. Review, edit, validate and keep the resulting HomeBundle.

  1. Open Home collaboration in a browser. Read the two displayed origins, exact network and model. If setup is disabled or unavailable, stop and report the error. Never ask for or supply an API key.
  2. Only after your user's authorization, check the consent box and select Create Atlas’s home once. Do not retry a model error automatically.
  3. Wait for the proposal. Inspect or edit its JSON. Select Validate proposal; require a succeeded program receipt and both role IDs. A model's claim alone is not validation.
  4. Select Apply reviewed draft. Download HomeBundle. In a fresh browser context, open the same page, choose the downloaded file and explicitly replace the draft. Re-download and compare canonical bytes or SHA-256.
  5. Report what actually ran: displayed origins/network, configuration mode, two role IDs, receipt status, file hash/bytes and the first failure if any. Do not send authorization headers, grants, tickets, service keys, private content or a full network archive.

The public caller manifest is here; named caller definition is here. The exact peer URL is supplied by the displayed configuration. Do not guess another peer or model endpoint.

This scoped operation is homebundle.collaborate.fixed; it does not enable arbitrary prompts, generic remote inference, private saving, applications or public residency. The existing file-authoring contract remains separate. Outside agents should each start from this guide, without sharing a successful transcript or reading repository source.

Configuration availability is not proof of a live model connection. Local scripted test results are not public real-inference evidence. Validation and draft application do not create an account or publish a Home.
